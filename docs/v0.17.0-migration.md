# Athanor v0.17.0 Migration Guide

v0.17.0 (S07 — Wave 2 of the plan/work skill split) collapses
`/athanor:deep-plan` and `/athanor:lite-plan` into the unified
`/athanor:plan` command via a `--depth=<value>` flag. This is the
clean-removal-plus-migration-doc path mandated by C4 — no shim files,
no per-tier wrapper SKILL.md.

## TL;DR

| You used to type | Now type | Notes |
|---|---|---|
| `/athanor:deep-plan` | `/athanor:plan --depth=deep` | Full adversarial: Planner A Claude + Planner B Codex cross-planning + 4-input Synthesis Critic. |
| `/athanor:lite-plan` | `/athanor:plan --depth=lite` | Lite tier: Planner A Claude only; Step 3 review + Step 4 critic skipped; `plan-a.md` copied to `plan.md`. |
| `/athanor:plan` | `/athanor:plan` (unchanged default) | Standard tier: Planner A Claude + Codex review + Refinement Critic. |
| n/a (new) | `/athanor:plan --no-review` | Orthogonal flag. Skips Step 3 review regardless of `--depth`. Compounds with deep / standard tiers; lite is unaffected. |

## Muscle memory still works

Trigger keywords previously routed by the standalone `/athanor:deep-plan`
and `/athanor:lite-plan` skill descriptions are now carried directly in
the unified `/athanor:plan` skill `description:` frontmatter. The Step 1
"Tier Classification" handler dispatches on these as the **fallback**
path when no `--depth=` flag is present:

- Deep-tier shorthand: `딥 플랜`, `deep plan`, `심층`,
  `교차 모델 계획`, `풀 플랜`.
- Lite-tier shorthand: `라이트 플랜`, `lite plan`, `간단한 계획`,
  `빠른`, `quick plan`.
- Standard-tier default: anything else (including the plain `플랜` /
  `plan` triggers).

So "딥 플랜 짜줘" still produces a deep-tier plan, and "라이트 플랜으로
빠르게 해줘" still produces a lite-tier plan. The flag form is the
new explicit interface; the keyword form keeps muscle memory intact.

## Flag dispatch ordering

The Step 1 handler (full body in
`skills/plan/references/depth-flag-dispatch.md`):

1. **First** parses `--depth` from the invocation arguments. Valid
   values: `standard | deep | lite`. If matched, binds `tier`
   directly and announces `Tier: <value> (--depth flag)`.
2. **Otherwise** runs the v0.16.x trigger-keyword heuristic above.
3. **Independently** parses `--no-review`. If present, binds
   `review_strategy=none` overriding the Codex availability matrix
   resolved at Step 0. The Step 3 / Step 4 dispatch table then
   skips the review round; the Critic uses its review-skipped variant
   (deep tier 2-input synthesis, or standard tier pass-through with
   `<!-- athanor:review-skipped -->` prefix).
4. Invalid values like `--depth=full` fall through to step 2 rather
   than erroring, so new synonyms can accumulate without breakage.

## What got deleted

- `skills/deep-plan/` directory (including its SKILL.md wrapper).
- `skills/lite-plan/` directory (including its SKILL.md wrapper).

The associated identity-surface regression tests
(`tests/test_regression_v012_native_identity_surface.py` and
`tests/test_regression_v011_1_using_superpowers_boundary.py`) had their
`NATIVE_THIN_LEADER_SKILLS` tuples shrunk 11 → 9 in the same commit
(atomic update — directory removal without tuple update would have
silently broken the boundary preamble assertions).

## What stayed the same

- `skills/plan/SKILL.md` Step 0 (Codex availability matrix), Step 2
  (planner dispatch), Step 3 (reviewer dispatch), Step 4 (critic), and
  Step 5 (presentation) all keep their existing tier-aware logic. The
  tier × `review_strategy` dispatch table is unchanged — only the
  `tier` resolution step at Step 1 grew the new flag-dispatch handler.
- The 7 reference companions under `skills/plan/references/` are
  unchanged in shape; `depth-flag-dispatch.md` was promoted from
  "forward-compat stub" to "active handler" framing.
- The Stop hook / PreToolUse Kernel Guard runtime gates are
  untouched — they fire on every Stop / pre-tool event regardless of
  which planning tier produced the turn.
- `/athanor:lfg` Step 1 still dispatches `/athanor:plan` for the
  cross-model planning identity step. LFG users can pass
  `--depth=deep` through to the planner if they want the deeper
  pipeline; the default standard-tier flow is unchanged.

## What this is NOT

- Not a rename of `/athanor:plan` itself.
- Not a CE / superpowers vendoring change — the v0.12.0 atomic cut
  already collapsed the vendored surface to 1 KEEP skill + 2 KEEP
  sub-agents + 5 absorbed concepts. S07 is purely about reducing the
  native plan-skill family from 3 SKILL.md files to 1.
- Not a behavior change for users who never typed `/athanor:deep-plan`
  or `/athanor:lite-plan` — those users see a richer skill description
  but no functional change in the standard tier.
