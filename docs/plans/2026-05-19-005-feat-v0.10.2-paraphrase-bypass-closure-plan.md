# feat: v0.10.2 — Stop hook paraphrase + NFKC + vendor-aware whitelist

## Summary

athanor v0.10.2 closes three honesty-arc-deferred items in the Stop hook
material-claim detector by *actually shipping* what v0.7.9's docstring had
incorrectly claimed:

- **B2 (sec-003 paraphrase bypass):** add a regex verb-anchor layer on top
  of the v0.7.7-derived literal whitelist so paraphrased claims like
  "CI is green" / "all tests are now green" / "테스트가 다 통과" no longer
  bypass the gate.
- **ADV-006 (cyrillic homoglyph):** apply Unicode `NFKC` normalization
  + a small confusables fold (Cyrillic letters that look identical to
  Latin equivalents) to the input message before substring matching. Same
  step also catches fullwidth-character variants.
- **A2 (vendor-aware whitelist):** extend `MATERIAL_CLAIMS_EN` and
  `MATERIAL_CLAIMS_KO` with idioms that vendored CE/superpowers skills
  emit but that aren't in the v0.7.7 set (e.g., "review complete",
  "implementation done", "<promise>DONE</promise>").

The change is **pure-Python stdlib only** (`re`, `unicodedata`). No new
dependencies; no behavioral change to skip-list categories (analysis,
planning, opinions, tool-output summaries). The honesty-arc story for
this release is "the v0.7.9 docstring promised these mitigations; v0.10.1
exposed that promise as unmet; v0.10.2 honors the promise."

---

## Problem Frame

`scripts/hooks/stop_verify_claims.py` `is_material_claim()` is currently
pure substring matching against literal phrase whitelists. Three known
bypass vectors live in residuals:

1. **Paraphrase bypass (B2):** a model that knows the whitelist can
   trivially rephrase ("tests pass" → "CI is green" / "all tests are
   passing", "build succeeded" → "the build is healthy now"). Cost of
   the bypass is one creative word.
2. **Cyrillic homoglyph (ADV-006):** a model that swaps Latin letters
   for Cyrillic look-alikes ("tеsts pass" with Cyrillic 'е') sails past
   substring matching because the bytes differ even though the rendered
   text is identical to the human eye.
3. **Vendor-aware gap (A2):** v0.10.0 absorbed ~50 vendored skills. CE
   skills emit completion idioms like "Review complete", "Residual
   actionable work: none", `<promise>DONE</promise>` that the v0.7.7
   whitelist (tuned to athanor-native voice) doesn't cover.

The first two were promised by the v0.7.9 hardening docstring; v0.10.1
U6 audit caught the overclaim and corrected the docstring honestly. v0.10.2
actually ships the work the docstring previously claimed.

## Scope

In-scope:

- New `_normalize_for_match(message)` helper that applies NFKC + a
  documented confusables fold (Latin↔Cyrillic look-alikes only,
  initially a conservative ~12-character set).
- New `MATERIAL_CLAIM_PATTERNS` regex list (compiled at module load)
  for verb-anchor paraphrase patterns. Targeted: "CI is green", "all
  tests (are )?(now |currently )?(green|passing)", "the build is
  healthy", "테스트(가| 가| 다)?(가| )?통과", etc. Conservative — fewer
  patterns is better than more; each pattern must have a verb anchor
  to avoid catching prose about tests.
- Extension of `MATERIAL_CLAIMS_EN`/`MATERIAL_CLAIMS_KO` with vendor-
  aware idioms (~10-15 new phrases).
- `is_material_claim()` refactored to: (1) normalize message, (2) check
  literal whitelist on normalized text, (3) check regex patterns on
  normalized text. Early return on first match.
- Regression tests: paraphrase positive cases (true positives), regex
  negative cases (true negatives — must not catch prose about tests),
  cyrillic homoglyph cases, fullwidth-character cases, vendor-aware
  whitelist additions.
- Docstring restoration: top-level docstring's "v0.7.9 hardening" block
  may now legitimately mention sec-003/ADV-006 closure with explicit
  v0.10.2 attribution. The v0.10.1 honesty correction reframing stays
  intact (we honestly say v0.10.1 found the overclaim and v0.10.2 fixed
  it; we don't pretend v0.7.9 shipped it).

Out-of-scope:

- LLM-class paraphrase patterns ("we verified the test suite ran clean"
  with subtle clause embedding). Regex layer is heuristic; v0.11.0+
  candidate for semantic similarity layer.
- Transcript-event introspection (sec-001 residual — adversarial nonce
  forgery). Separate concern; same v0.11.0+ window.
- Mid-session profile mutation guard.
- Adding regex to KO whitelist beyond the verb-stem patterns. KO
  morphology is rich; a single comprehensive regex would either over-
  catch or under-catch. v0.10.2 adds 3-4 KO regex patterns max; rest
  stay as literal substrings.
- Sentence-level attribution detection ("the v0.7.6 docs said 'tests
  pass'" — quoted historical reference that contains trigger phrase).
  v0.10.3+ candidate.

## Key Decisions

- **D1 — Conservative confusables fold, not full Unicode confusables
  database.** A full confusables database (`unicodedata` doesn't include
  it; would require shipping data from `python-confusable-homoglyphs` or
  similar) is overkill for v0.10.2. We hand-pick the ~12 Cyrillic letters
  that are visually indistinguishable from Latin equivalents at common
  font sizes:
  `а→a, е→e, о→o, р→p, с→c, у→y, х→x, А→A, В→B, Е→E, К→K, М→M, Н→H, О→O, Р→P, С→C, Т→T, Х→X`.
  Document the set in code with a regression test asserting each entry's
  fold. If the gate misses an attack on another homoglyph (e.g., Greek
  `ο` for Latin `o`), document the residual and expand deliberately,
  not greedily.
- **D2 — Regex patterns are verb-anchored.** Every paraphrase pattern
  must include a verb anchor (`is`, `are`, `was`, `passed`, etc.) to
  reduce false positives on prose discussing tests without claiming
  state ("when tests pass through this filter..." should NOT trigger
  the gate). Patterns use `\b` word boundaries and `re.IGNORECASE`.
- **D3 — Patterns compile at module load, fail-loud on regex error.**
  Module-load assertion `assert MATERIAL_CLAIM_PATTERNS` prevents an
  empty list from silently disabling the layer. Each pattern is
  compiled in a try/except; a bad regex would raise at import time and
  the Stop hook would refuse to load (fail-loud), not silently degrade
  to substring-only.
- **D4 — Normalize before BOTH whitelist and regex checks.** A single
  normalization call at the top of `is_material_claim()` so both layers
  benefit. NFKC + confusables fold are idempotent so the cost is
  one normalize per message.
- **D5 — Vendor-aware additions stay in `MATERIAL_CLAIMS_EN`/`_KO`,
  not in a separate list.** A2's value is "more phrases the gate
  catches" — there's no operational reason to segregate vendor-derived
  phrases. Document the v0.10.2 additions inline with a comment
  identifying provenance ("vendored-skill idiom").
- **D6 — Performance contract.** `is_material_claim()` must stay O(n)
  in message length. NFKC normalization is O(n); confusables fold via
  `str.translate()` is O(n); each regex pattern is O(n) in worst case.
  With ~12 patterns total the overall cost stays well below 1ms for
  typical Stop event payloads. No regression test on timing (CI runner
  noise too high); just keep the pattern count bounded.
- **D7 — Honesty arc handling of the docstring.** The v0.10.1
  correction stays. The v0.10.2 docstring update adds a new
  "v0.10.2 paraphrase + NFKC closure" subsection that explicitly says:
  "v0.10.1 documented these as deferred after the v0.7.9 docstring
  overclaim audit; v0.10.2 actually ships the regex + NFKC + confusables
  fold layers." Both the old v0.7.9 history and the v0.10.1 correction
  remain visible; v0.10.2 closure is its own subsection.

## Implementation Units

### U1. `_normalize_for_match()` helper — NFKC + confusables fold

**Goal:** Single normalization function applied at the top of
`is_material_claim()`. Closes ADV-006 cyrillic homoglyph and fullwidth-
character attacks.

**Requirements:** D1, D4, D6.

**Dependencies:** none.

**Files:**
- Modify: `scripts/hooks/stop_verify_claims.py` — add `import unicodedata`;
  add `_CYRILLIC_TO_LATIN` translation table; add `_normalize_for_match(text)`.

**Approach:** `unicodedata.normalize("NFKC", text)` first (collapses
fullwidth, ligatures, etc.); then `str.translate(_CYRILLIC_TO_LATIN_TABLE)`
to fold the 17 Cyrillic look-alikes to Latin equivalents. Lowercase at the
end (matches existing `lowered = message.lower()` semantics for EN
whitelist; KO matching stays case-irrelevant because Korean has no case).

**Test scenarios:**
- happy: ASCII "tests pass" → unchanged.
- happy: NFKC "ｔｅｓｔｓ ｐａｓｓ" (fullwidth) → "tests pass".
- happy: cyrillic "tеsts pass" (Cyrillic 'е') → "tests pass".
- edge: empty string → empty string.
- edge: mixed cyrillic + fullwidth "ｔеsts ｐass" → "tests pass".
- edge: non-confused characters (Greek 'ο' for Latin 'o') stay as-is.
  Document this as known residual; cover with a "limitation" test.

**Verification:** `tests/test_regression_v010_2_paraphrase_closure.py`
test functions for each scenario.

**Execution note:** Test-first.

### U2. Paraphrase regex layer — `MATERIAL_CLAIM_PATTERNS`

**Goal:** ~8-12 conservative regex patterns that catch verb-anchored
paraphrases of test-pass / build-success / deploy / verification claims.

**Requirements:** D2, D3.

**Dependencies:** U1 (normalization applied before regex).

**Files:**
- Modify: `scripts/hooks/stop_verify_claims.py` — new constant
  `MATERIAL_CLAIM_PATTERNS` with compiled regexes; assert at module
  load; integrate into `is_material_claim()` after literal-whitelist
  check.

**Approach:** Each pattern is a single regex. Examples (final list
finalized in implementation; below is directional):
- `r"\bci\s+(is\s+)?(now\s+|currently\s+)?(green|passing|healthy)\b"` — "CI is green" / "CI now passing"
- `r"\ball\s+tests\s+(are\s+)?(now\s+|currently\s+)?(green|passing)\b"` — "all tests are now green"
- `r"\bthe\s+build\s+(is\s+)?(now\s+|currently\s+)?(green|healthy|clean|passing)\b"` — "the build is now healthy"
- `r"\b테스트(가|는)?\s*(다|모두|전부)?\s*통과(했|함)"` — Korean variant
- `r"\bdeployed\s+(it\s+)?(to|onto)\s+(prod|production|main)\b"` — paraphrase of "deployment succeeded"
- (More TBD; cap at ~12. Quality over quantity.)

Every pattern includes a verb anchor and uses `\b` word boundaries.

**Test scenarios:**
- positive: "CI is now green" → caught.
- positive: "All tests are passing" → caught.
- positive: "The build is healthy" → caught.
- positive: "테스트가 모두 통과했습니다" → caught (via existing KO literal OR new regex; either is fine).
- negative: "When tests pass through this filter, the user sees..." → NOT caught (verb anchor is "pass" but context is wrong; regex requires "tests are/were/now pass").
- negative: "I'll check if CI is green later." → NOT caught (the prose is talking about a future check, not asserting state). This is a hard case — the regex WILL catch it. Document as known residual: regex layer cannot distinguish assertive from speculative tense without semantic analysis. v0.10.3 candidate.
- negative: pure prose about tests → not caught.

**Verification:** dedicated test file (`test_regression_v010_2_paraphrase_closure.py`).

**Execution note:** Test-first (write positive + negative cases as
parametrized tests BEFORE adding patterns; ensure RED on every case
first).

## Risk Analysis & Mitigation

| Risk | Severity | Mitigation |
|---|---|---|
| Regex pattern over-catches prose ("CI is green later" speculative claim) | Medium | Conservative patterns with verb anchors; document residual in code; v0.10.3 attribution detection candidate |
| Cyrillic fold list under-catches some homoglyphs (Greek, Armenian) | Low | Document the 17-char Latin↔Cyrillic set as the v0.10.2 scope; expand deliberately in future releases |
| Module-load failure if a regex has a typo | Low | Each pattern compiled in try/except with assert; fail-loud at import (Stop hook refuses to load — better than silent degradation) |
| Performance regression on large Stop payloads | Low | All layers O(n); pattern count capped; no test on timing (noise) but informal benchmark in commit body |
| False positives on vendored skill output ("the agent task completed" already in whitelist) | Low | Whitelist extension is additive; no removals; existing protection unchanged |
| Honesty arc — over-restoration of v0.7.9 docstring | Medium | Plan §D7 explicit: v0.10.1 correction stays visible; v0.10.2 closure is its OWN subsection, not a backfill of v0.7.9 history |
