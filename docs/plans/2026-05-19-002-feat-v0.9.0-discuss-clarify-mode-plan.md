# feat: v0.9.0 — /athanor:discuss에 clarify 모드 추가 (intent 명확화)

## Summary

`/athanor:discuss` 스킬을 확장해서 **clarify** (intent 명확화) + **synthesis** (옵션 A/B 합성, 기존) 두 모드를 가진다. 새 명령어 신설 없이 기존 surface 안에서 흡수. Step 1에서 leader가 user에게 한 번 묻고 모드 분기. clarify 모드는 single-Claude dialog로 ce-brainstorm Standard tier gap probe (evidence/specificity/counterfactual/attachment)를 진행하고 `.athanor/sessions/{id}/requirements.md`를 산출. 끝나면 user가 다음 단계 메뉴에서 선택 — plan / synthesis chain / analyze / stop. `/athanor:plan` Step 1은 자동으로 requirements.md를 추가 input으로 로드 (없으면 backwards compat).

---

## Problem Frame

`/athanor:discuss`는 현재 옵션 A/B가 이미 정해진 dilemma만 처리 (skills/discuss/SKILL.md Step 1). 모호한 의도로 들어온 사용자는 옵션을 무리하게 만들거나 `/athanor:plan`으로 곧바로 가서 plan이 product behavior를 발명하게 됨. ce-brainstorm은 이미 검증된 4-lens gap probe 패턴을 제공하므로 athanor도 등가물을 `/athanor:discuss` 안에서 제공한다 (origin: brainstorm §Problem Frame).

## Requirements

**Mode dispatch (Step 1)**

- R1. `/athanor:discuss` Step 1은 user에게 모드 선택 질문을 1회 발화한다. 3개 옵션: (a) 옵션 A/B 명확 → synthesis, (b) 의도 명확화 필요 → clarify, (c) 잘 모르겠다 → clarify default (origin R1).
- R2. user 응답으로 즉시 분기. 자동 모드 감지 없음 (origin R2).

**Clarify mode dialog**

- R3. clarify dialog는 single-Claude로 진행. parallel workers 없음, Codex 없음 (origin R3).
- R4. ce-brainstorm Standard tier 4 gap lenses 채택 — evidence / specificity / counterfactual / attachment. 각 lens는 user opening에 해당 gap이 있을 때만 fire (Phase 1.2 internal scan) (origin R4).
- R5. dialog는 ce-brainstorm Interaction Rules 따름 — one question per turn, AskUserQuestion 우선, introspective probe는 open-ended (origin R5).
- R6. dialog 종료 시 `.athanor/sessions/{id}/requirements.md` 산출. ce-brainstorm requirements-capture 템플릿 (frontmatter / Summary / Problem Frame / Actors A-IDs / Key Flows F-IDs / Requirements R-IDs / Acceptance Examples AE-IDs / Success Criteria / Scope Boundaries / Key Decisions / Dependencies / Outstanding Questions) (origin R6).

**Synthesis mode (backwards compat)**

- R7. synthesis 모드의 모든 동작 (현재 skills/discuss/SKILL.md Step 2-4)은 v0.9.0에서 변경 없음 (origin R7). **회귀 잠금**: U1 신규 test가 synthesis 분기 prose + 기존 worker dispatch contract (Researcher / Devil's Advocate / Step 2.5 stop-phrase defense / Critic / Step 4 Present Results)를 텍스트 fixture grep으로 pinning.

**Plan integration**

## Key Technical Decisions

- **새 skill 신설 vs `/athanor:discuss` 흡수**: 후자 채택. surface 잡음 회피.
- **Step 1 mode question vs 자동 감지**: explicit question 채택. false-positive 회피.
- **clarify dialog 구조**: single-Claude (no workers, no Codex). ce-brainstorm 단일 agent 패턴 일관성.
- **Gap probe scope**: Standard tier 4 lenses. Deep-product durability는 v0.9.1+.
- **Output file 분리**: `requirements.md` (clarify) + `discuss.md` (synthesis). frontmatter mode-field 통합 대안은 plan-side parsing 복잡성으로 기각.
- **Phase 4 handoff**: stop-after-requirements + user menu. 자동 chain 기각.
- **Plan integration**: plan Step 1이 자동으로 requirements.md 로드 (있으면). 부재 시 backwards compat.
- **ce-brainstorm references 처리**: requirements-capture 템플릿을 `skills/discuss/references/requirements-capture.md`에 vendor (T2 패턴, MIT 호환). gap-probe 가이드는 `skills/discuss/references/clarify-gap-probes.md`에 별도 vendor. SKILL.md inline에 핵심만 embed.

### U2. skills/discuss/SKILL.md — clarify dialog protocol

**Goal:** clarify 모드 진입 시 single-Claude dialog가 ce-brainstorm Standard tier 패턴으로 동작. Phase 1.2 internal gap scan + Phase 1.3 probe protocol + Phase 2.5-style scoping synthesis + integration check.

**Requirements:** R3, R4, R5

**Dependencies:** U1 (mode dispatch가 분기 가능해야 발동)

**Files:**
- Modify: `skills/discuss/SKILL.md` (신규 Step 2-clarify 섹션)

- Test: `tests/test_regression_clarify_dialog_protocol.py` (new — **owned by this unit, write FIRST**)

**Approach:**

신규 섹션 `### Step 2-clarify: Single-Claude Dialog (clarify mode)` 추가:

1. Phase 1.2 internal scan prose — 4 gap lenses 명시:
   - **Evidence gap**: opening이 want/need 주장하지만 구체적 행동 (시간/돈/workaround) 가리키지 않으면 fire
   - **Specificity gap**: beneficiary가 추상 레벨이라 발명 없이 설계 불가하면 fire
   - **Counterfactual gap**: 현재 workaround와 비용이 가시화 안 됐으면 fire
   - **Attachment gap**: 특정 솔루션 shape에 attach됐고 더 작은 변형 안 시험됐으면 fire

2. Phase 1.3 dialogue protocol prose:
   - One question per turn (Rule 1)
   - AskUserQuestion 기본 (Rule 4)
   - Introspective probe는 open-ended (Rule 5)
   - 각 active gap당 1개 open-ended probe (rigor probe)
   - 모든 gap probe 끝나면 integration check → 미충족 사항 1개 추가 probe

3. Phase 2.5-style scoping synthesis 발화:
   - "What we're building" 1-3 sentences
   - "Key trade-offs" 1-3 bullets (조건부)
   - "What's not in scope" 1-3 bullets (조건부)
   - "Call outs" 0-3 bullets (조건부)
   - user 확정 요청

4. user 확정 시 U3 (requirements.md 작성)로 이동

**Stop-phrase guard (clarify dialog 안)**: Codex 사전 리뷰 P1 #6 반영. clarify dialog는 single-Claude이므로 기존 Step 2.5 Worker Output Defense (re-dispatch 메커니즘)는 적용 불가하지만, leader가 dialog 진행 중 자기 발화에 "계속할까요?" / "이 정도면 멈출까요?" 같은 stop-phrase를 쓰면 안 됨을 prose에 명시. dialog가 자연스럽게 종료 시점에 도달하기 전까지 단발성 stop-phrase로 끝내지 않음. (사용자가 의사 표시로 종료하는 것은 별개.)

## Risks & Mitigations

- **Step 1 mode question이 user에 마찰**: 매번 모드 묻기는 reverbating일 수 있음. *Mitigation*: 짧고 단발성 (AskUserQuestion 1회). v0.10.0+에서 첫 운용 데이터 기반 자동 분류 재검토.
- **clarify dialog가 athanor 평균 사용 규모에 과중**: ce-brainstorm Standard tier는 의도 명확화에 충실하지만 작은 task엔 무거움. *Mitigation*: Phase 1.2 internal scan이 active gap만 fire (4개 모두 발동 아님). 작은 task는 0-1 probe로 종료 가능.
- **requirements.md와 discuss.md의 역할 혼동**: 동일 session에 둘 다 있을 수 있음 (clarify 후 chain → synthesis). *Mitigation*: 파일명 분리 + 각자 명시 mode. plan Step 1은 둘 다 (있으면) inject 가능.
- **single-Claude dialog가 cross-model 합성보다 약함**: synthesis는 Codex 활용하지만 clarify는 single-Claude. *Mitigation*: ce-brainstorm 자체가 single-agent로 검증됨. v0.9.x에서 cross-model 옵션 후보.
- **trigger keyword 충돌 가능성**: clarify-방향 키워드 ("헷갈려")가 다른 skill ('/athanor:debug')과 잠재 충돌. *Mitigation*: 기존 athanor trigger collision policy 재사용 — 가장 구체적 매치 우선. 충돌 시 user에 disambiguate.
- **plan Step 1의 input 순서**: discuss.md + analyze.md + requirements.md 셋 다 있을 때 ordering. *Mitigation*: U5 prose에서 ordering 명시 — analyze.md (코드 기반) → requirements.md (intent) → discuss.md (옵션 합성). plan-time 컨텍스트 우선순위.
- **honesty arc 위반 가능성**: "intent-clarification enforced" 같은 표현이 흘러들어갈 수 있음. *Mitigation*: U6의 honesty 회귀 테스트 negative assertion.
