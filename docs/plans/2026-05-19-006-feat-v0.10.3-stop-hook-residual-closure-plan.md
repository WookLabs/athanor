# feat: v0.10.3 — Stop hook residual closure

## Summary

athanor v0.10.3 closes the three Stop-hook accuracy residuals that v0.10.2
documented honestly (rather than hand-wave away):

- **R1 — Greek/Armenian homoglyph fold extension.** v0.10.2's Cyrillic-only
  fold left Greek `ο` (U+03BF) and Armenian `ո` (U+0578) unfolded. v0.10.3
  extends `_CYRILLIC_TO_LATIN_TABLE` (renamed to `_CONFUSABLES_TO_LATIN_TABLE`)
  with ~10-12 additional Greek + Armenian Latin look-alikes. Same fold step,
  same NFKC pre-pass, no new code path.
- **R2 — Conditional / speculative tense suppression.** v0.10.2 regex layer
  catches "If all tests are green, merge" as a false positive. v0.10.3 adds
  a *clause-prefix check*: when a match is found, the regex layer inspects
  the clause start (after the nearest preceding punctuation: `. , ; \n ?`)
  for conditional/speculation markers (`if`, `once`, `when`, `should`,
  `could`, `would`, `만약`, `만일`, `... 면`, `... 한다면`). If found, the
  match is suppressed. Substring whitelist matching is NOT affected
  (literal "tests pass" still triggers — that's v0.7.7 behavior, not a
  regression introduced by v0.10.3).
- **R3 — Attributed historical reference skip.** v0.10.2 noted that
  `the v0.7.6 docs said "tests pass"` would trigger the gate even though
  it's an attributed historical quote. v0.10.3 adds a *quoted-context
  check*: when a match is found INSIDE a quoted span (matched pairs of
  `"..."`, `'...'`, `` `...` ``, or following `said`/`claimed`/`wrote`/`라고`
  within ~30 chars before the match), suppress it.

All three are heuristic — they will misfire in ambiguous edge cases. The
plan accepts a small false-negative trade-off (a real assertion phrased
conditionally is missed) in exchange for the much-more-common false-
positive reduction. No new dependencies; pure stdlib `re` and `unicodedata`.

Plan reference: closes v0.10.2 §Deferred (R1/R2/R3 — the three "v0.10.3
candidate" residuals).

## Problem Frame

v0.10.2 closed the v0.7.9 paraphrase / NFKC / vendor-aware overclaim, but
left three accuracy residuals visible in the v0.10.2 docstring and CHANGELOG:

1. **Greek/Armenian homoglyph attack surface.** A model that knows the
   v0.10.2 fold table can substitute Greek `ο` for Latin `o` and bypass
   substring matching. Same attack vector as Cyrillic — the byte differs,
   the render is identical.
2. **Conditional/speculative false-positives.** "If tests are green, merge"
   and "Once the build is healthy, ship" trigger the v0.10.2 regex layer
   even though the speaker isn't asserting state. v0.10.2 acknowledged this
   in `test_known_false_positives_documented()` as a current-behavior pin
   awaiting v0.10.3 closure.
3. **Attribution false-positives.** Quoted historical text
   (`'the v0.7.6 docs said "tests pass"'`) triggers the gate by matching
   the literal whitelist phrase inside the quote. Document- and review-
   workflow turns that reference older state are commonly affected.

v0.10.3 closes all three with conservative heuristics. The honesty-arc
narrative continues: each residual documented in the release where it was
identified, then closed in a subsequent release. No silent fixes; no
overclaim.

## Key Decisions

- **D1 — Heuristic, not semantic.** Both conditional/speculative
  suppression and attribution skip use string-match heuristics over a
  fixed marker set. Edge cases will misfire. The trade-off: small false-
  negative rate (real claim phrased conditionally is missed) is
  acceptable; large false-positive rate (every doc reference triggers gate)
  is not. Document marker sets inline; expand deliberately if a real
  attack vector emerges.
- **D2 — Match-position tracking.** `is_material_claim()` refactored to
  capture (phrase, position) pairs for literal matches and use
  `re.Pattern.search()` (returning Match objects) for regex matches.
  Both check context BEFORE returning True.
- **D3 — Conditional marker set is intentionally small.** EN: `if`,
  `once`, `when`, `should`, `could`, `would`, `unless`. KO: `만약`, `만일`,
  `~면`, `~한다면`. ~10 markers total. Each tested against the start of
  the clause containing the match. A clause boundary = preceding `.`,
  `,`, `;`, `?`, `!`, or newline. Search window: from the most recent
  clause boundary to the match start, look for any marker as the first
  whitespace-separated token.
- **D4 — Attribution markers cover both quotes and verbs.** Quote
  characters: `"`, `'`, `` ` `` — match within a paired span (most
  recent opening quote of the same character before match start, paired
  with the next closing quote after match end). Attribution verbs:
  `said`, `claimed`, `wrote`, `noted`, `commented`, `said:`, `라고 했`,
  `라고 적`. Verb context window: 30 characters before match start.
- **D5 — Context checks apply to BOTH literal AND regex matches.** An
  attributed `'tests pass'` should be suppressed whether the match came
  from substring whitelist or paraphrase regex. Same suppression logic
  for both layers; single call site.
- **D6 — Existing v0.10.2 known-residual tests will invert.** v0.10.2
  pinned the false-positive cases with explicit "if these flip, residual
  was closed" comments. v0.10.3 closes them; the tests invert their
  assertion. This is the canonical mechanism — current-behavior pins
  are intentional flippers, not regressions.
- **D7 — Performance contract preserved.** Context checks are O(context-
  window) per match, with the window ≤ 50 chars. Total cost stays
  O(n × number-of-patterns) — unchanged from v0.10.2.

## Implementation Units

### U1. Confusables table extension (Greek + Armenian)

**Goal:** Extend `_CYRILLIC_TO_LATIN_TABLE` (renamed
`_CONFUSABLES_TO_LATIN_TABLE`) with ~10-12 Greek and Armenian look-alikes
that target Latin substring matches.

**Files:** `scripts/hooks/stop_verify_claims.py` — rename constant; add
entries.

**Approach:** Conservative — only characters that are visually
indistinguishable at common font sizes. Initial set (final list refined
at implementation time):

- Greek lowercase: `ο→o` (U+03BF), `ν→v` (U+03BD), `ρ→p` (U+03C1),
  `α→a` (U+03B1), `ε→e` (U+03B5), `υ→u` (U+03C5)
- Greek uppercase: `Α→A`, `Ε→E`, `Ι→I`, `Ο→O`, `Ρ→P`, `Τ→T`, `Υ→Y`
- Armenian: `ո→o` (U+0578)

(The Armenian set is intentionally tiny — most Armenian letters have
distinguishable shapes; only `ո` matches Latin `o` cleanly. Add more if
attack evidence justifies.)

Existing test
`test_normalize_non_confused_greek_omicron_documented_residual` inverts:
Greek `ο` is now folded; the assertion should flip.

**Test scenarios:**
- positive: "tests p" + Greek `ο` + "ss" folds to "tests poss" → wait,
  the cyrillic fold worked on this in v0.10.2 docstring example. Let me
  re-check. Actually "tests pass" written with Greek `ο` for the `o` in
  "pass" produces "tests p" + `ο` + "ss". After fold: "tests poss"? No —
  the fold replaces `ο` with `o`, so the result is "tests pass". My
  v0.10.2 test `test_normalize_non_confused_greek_omicron_documented_residual`
  asserted Greek `ο` stays as-is in v0.10.2; v0.10.3 inverts it.
- positive: "deployed t" + Greek `ο` (U+03BF) + " production" — fold to
  "deployed to production" — caught by U2 deploy regex.
- negative: pure ASCII unchanged (no regressions).

**Verification:** new tests + v0.10.2 inversion test green.

**Execution note:** test-first (invert v0.10.2 known-residual test
first, observe RED, then add fold entries).

### U2. Conditional/speculative tense suppression

**Goal:** When a phrase OR regex pattern matches, inspect the
*clause start* (the segment from the most recent punctuation boundary
to the match position) for conditional/speculation markers. If found,
suppress the match.

**Files:** `scripts/hooks/stop_verify_claims.py` — new
`_is_conditional_or_speculative_context(text, match_start)`.

**Approach:** `re.finditer` over a small "boundary characters" set (`.`,
`,`, `;`, `?`, `!`, `\n`) to find the nearest preceding boundary. Take
the substring from that boundary (or text start) to match_start. Strip
whitespace. Check if the first whitespace-separated token (lowercased) is
in `_CONDITIONAL_MARKERS_EN` or if the strip starts with a Korean marker
in `_CONDITIONAL_MARKERS_KO`.

Marker sets:
- EN: `{"if", "once", "when", "should", "could", "would", "unless",
  "whenever", "as soon as"}`
- KO: `{"만약", "만일"}` (suffix markers like `~면`/`~한다면` are
  prefix-bound in Korean; the simple prefix check catches the common
  "만약 / 만일 ... 면" pattern; pure "...면" without prefix marker is
  ambiguous and intentionally NOT caught)

The check runs BEFORE returning True in `is_material_claim()`. The
attribution check (U3) runs in parallel.

**Test scenarios:**
- positive: "If all tests are green, merge." → suppressed (v0.10.2
  inversion).
- positive: "Once the build is healthy, ship it." → suppressed.
- positive: "Should the deploy succeed, notify the team." → suppressed.
- positive: "만약 테스트가 통과한다면 머지하세요." → suppressed.
- negative: "All tests are green. Merge confirmed." → caught (no
  conditional prefix on "All tests are green").
- negative: "CI is green, by the way." → caught (no conditional).
- negative: "I if all tests are green I think" — adversarial edge case.
  Conservative behavior: suppressed because the clause "I if..."
  starts with "I" (not a marker), so it stays caught. Actually the
  marker check is on the *first token*. "I" is first; not in marker
  set; no suppression. Document this nuance.

**Verification:** new tests in `test_regression_v010_3_residual_closure.py`.

### U3. Attribution / quoted-context skip

**Goal:** When a match falls inside a quoted span or shortly after an
attribution verb, suppress it.

**Files:** `scripts/hooks/stop_verify_claims.py` — new
`_is_attributed_quote_context(text, match_start, match_end)`.

**Approach:** Two sub-checks:

1. **Paired quote check.** For each quote char (`"`, `'`, `` ` ``), find
   the most recent opening occurrence before `match_start` and the next
   occurrence after `match_end`. If both exist on the same line (i.e.,
   no `\n` between them), the match is inside a quote. Return True.

2. **Attribution verb check.** Look at the 30 characters before
   `match_start` (within the same line). If any of the EN attribution
   markers (`said`, `claimed`, `wrote`, `noted`, `commented`, `mentioned`,
   `stated`) or KO markers (`라고 했`, `라고 적`, `라고 말`) appears, the
   match is attributed. Return True.

Both checks fail-open (false on ambiguity). If neither sub-check fires,
return False (don't suppress).

**Test scenarios:**
- positive: `the v0.7.6 docs said "tests pass" back then` → match is in
  quote → suppressed.
- positive: `He claimed: tests pass.` → "claimed:" precedes match within
  30 chars → suppressed.
- positive: `'review complete' was the assertion` → match in quote →
  suppressed.
- negative: `tests pass after my changes` → no quote, no attribution →
  caught.
- negative: `review complete.` (standalone) → caught.
- edge: multi-line quote: `said\n"tests pass"` → opening quote on next
  line; closing-quote check requires same-line; check fails → suppressed
  via attribution verb branch (since "said" precedes within 30 chars
  even across newlines if we strip the newline from the window). Decide
  in implementation; document.

**Verification:** new tests.

### U4. Refactor `is_material_claim()` for position tracking + suppression

**Goal:** Update detection pipeline to track match position and apply
both context checks before returning True.

**Files:** `scripts/hooks/stop_verify_claims.py`.

**Approach:** Replace `if phrase in normalized: return True` with
`pos = normalized.find(phrase); if pos >= 0 and not _is_attributed_quote_context(message, pos, pos+len(phrase)) and not _is_conditional_or_speculative_context(message, pos): return True`.
Same logic for regex matches via `match.span()`.

Note: position tracking uses the ORIGINAL message (not normalized) for
context checks — the suppression markers are not normalized themselves;
checking against normalized text would also be valid but `message`
preserves the user's original case for cleaner debugging.

Korean literal matches still use the dual raw-or-normalized check;
context suppression checks the position in whichever side matched.

**Test scenarios:** Cross-cutting in U2 / U3 tests.
