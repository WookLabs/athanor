# Plan B: v0.12.0 Concept Kernel Cutover - Alternative Approach

## Goal

v0.12.0 should stop pretending athanor is stronger because it exposes 46
third-party skills as `/athanor:ce-*` and `/athanor:sp-*`. The goal is to
make athanor smaller, sharper, and more honest:

- Keep the 10 athanor-native commands as the user-facing product surface.
- Remove the vendored CE/superpowers command surface in one v0.12.0 cut.
- Absorb the useful concepts as structured runtime data consumed by
  athanor-native skills.
- Preserve the real v0.10.0 through v0.11.7 fixes as release evidence,
  regression tests, and architectural lessons, without defending the
  over-scoped command surface.

The core move: transform "vendored skills as commands" into an
`concepts/` kernel. Reviewer personas, requirements-capture shapes,
debugging discipline, TDD discipline, skill-discovery policy, and ship
pipeline patterns become data and native prompt contracts. They stop being
separate slash commands.

## Approach

Use a **concept kernel cutover**: introduce a small JSON concept registry,
rewire native skills to read from it, then delete the `ce-*` / `sp-*`
surface in the same release. No deprecation wrapper. No multi-release
"soft landing." No triage matrix that spends a release asking which
vendored commands deserve to stay.

This beats phased deprecation because phased deprecation optimizes the
wrong thing. The harm is not that users might lose `/athanor:ce-plan`; the
harm is that every release with `/athanor:ce-plan` present teaches the
wrong ontology: athanor as a cargo plugin whose value is breadth. The user
has clarified that the intended ontology is concept absorption into
athanor-native orchestration. A deprecation window preserves the mistaken
product shape exactly when the project needs a crisp correction.

The v0.11.3 through v0.11.7 companion-fix arc proves the key distinction:
the shipped fixes are valuable, but they are not evidence that the
vendored command surface was correct. The fixes closed input-layer parsing,
plugin-root path resolution, doc drift, sentinel binding, scanner scope,
and profile-mutation detection. Those are athanor infrastructure truths.
They survive because the hook, tests, documentation discipline, and release
honesty survive. The `ce-*` / `sp-*` command surface does not need to
survive for that value to remain real.

## Risks

1. **Risk: Users who started using `/athanor:ce-*` or `/athanor:sp-*` lose
   commands without warning.**
   Mitigation: Make v0.12.0 intentionally breaking and honest. Put the
   migration note in README, CHANGELOG, and CLAUDE.md: use the upstream
   CE/superpowers plugins directly if you want their command surfaces; use
   athanor for the native concept-absorbed orchestrator. Do not pretend a
   wrapper is compatibility.

2. **Risk: Concept registry becomes vendoring by another name.**
   Mitigation: Cap concepts by purpose, not source file count. The registry
   check should fail if entries expose slash commands, copy long upstream
   prose, or exceed a reasonable size threshold without explicit rationale.

3. **Risk: Removing CE reviewer agents weakens `/athanor:review`.**
   Mitigation: Keep the high-value persona distinctions as data in
   `concepts/review-personas.json`, then inject them into native reviewer
   prompts. The dispatch model remains athanor-native Thin Leader workers,
   but the persona vocabulary survives.

4. **Risk: The v0.11.3-v0.11.7 companion-fix arc gets accidentally
   deleted with vendoring cleanup.**
   Mitigation: Treat the Stop-hook companion tests as protected. Phase 4
   explicitly preserves v0.11.3 input-layer, v0.11.6 sentinel binding, and
   v0.11.7 profile-mutation tests. Phase 0 creates the honesty ledger
   before deletion work starts.

5. **Risk: Documentation scanners falsely flag historical v0.10 material.**
   Mitigation: Extend the existing historical-context exemption pattern in
   `tests/test_regression_v011_5_claude_md_invariants.py` so old plans and
   the new archive can discuss vendoring historically, while README,
   CLAUDE.md, STATE, DESIGN, and DEPENDENCIES must state current truth.

6. **Risk: Licensing gets muddier after moving from copied files to
   concepts.**
   Mitigation: `NOTICE.md` and `concepts/registry.json` keep per-concept
   `source` and `source_paths`. Copied files still require provenance
   blocks. Absorbed ideas get attribution without pretending the source
   files are shipped.

7. **Risk: Native skills become too long after absorbing concept text.**
   Mitigation: Store reusable detail in `concepts/*.json` and short
   reference docs. Native skills should name the concept IDs and give
   execution rules, not paste entire upstream workflows.

8. **Risk: Atomic removal causes a large noisy diff.**
   Mitigation: Do it as one clearly named v0.12.0 change, but organize the
   implementation commits by phase: ledger, registry, native rewiring,
   deletions, tests/docs, release gates. The release is atomic; the git
   history can still be reviewable.

9. **Risk: The release looks like a rollback instead of an architectural
   improvement.**
   Mitigation: Use the phrase "concept absorption" consistently. The
   release removes the wrong interface, not the learning. The companion-fix
   arc is named as evidence that Athanor got stronger during the detour.

10. **Risk: Third-party upstream updates become harder to notice without
    `check_vendor_drift.py`.**
    Mitigation: Replace drift checking with concept-source review. A future
    upstream release should trigger "do any concepts need revision?" rather
    than "does our vendored copy differ byte-for-byte?"

## Why This Alternative?

The standard deprecation plan assumes compatibility is the main value.
Here, compatibility is the liability. A long deprecation period preserves
the exact command names that encode the mistaken decision:
`/athanor:ce-*` and `/athanor:sp-*`.

This alternative is different in three concrete ways:

- **It changes the representation.** The useful material becomes
  structured concept data and native prompt contracts, not markdown skills
  under new names.
- **It cuts the surface atomically.** v0.12.0 is a breaking truth release,
  not the start of a slow apology.
- **It honors the detour without defending it.** The companion-fix arc is
  preserved as Athanor infrastructure progress. The cargo surface is
  removed as a product-shape mistake.

The result is a plugin that is easier to understand:

- `/athanor:plan` means Athanor planning.
- `/athanor:work` means Athanor work.
- `/athanor:review` means Athanor review.
- Concepts from CE and superpowers improve those flows internally.
- Users who want CE or superpowers as products should install those
  products directly.

That is closer to the original intent than any deprecation wrapper can be.
