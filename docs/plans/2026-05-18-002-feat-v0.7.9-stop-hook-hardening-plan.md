# feat: v0.7.9 — Stop hook hardening (sentinel binding + project-root scoping + paraphrase expansion)

## Summary

v0.7.8 delivered the spike-promised Stop-hook enforcement upgrade (`type: command` + `exit 2` blocking, per docs/STATE.md §"Command-hook Stop blocking spike (2026-05-18)"). PR #16's 7-reviewer ce-code-review surfaced **three P0 architectural bypass paths** that the v0.7.8 design accepted as deferred:

1. **Sentinel forgery** — any response with `<!-- athanor:verification-emission v=1 -->` as line 1 bypasses the gate; the sentinel is a publicly documented bare string with no integrity binding.
2. **Parent-directory athanor.json hijack** — `_find_athanor_config` walks 8 levels up; an ancestor's `profile: "off"` silently disables the gate without the user knowing which config did it.
3. **Paraphrase bypass** — literal substring matching evaded by "CI is green", "verified the suite", "rolled out to production", "PR landed", etc. v0.7.7's semantic prompt was lost in the v0.7.8 lexical port.

v0.7.9 closes all three within one release (same bundling pattern as v0.7.8 closing M1+M2+C2). Plus two cheap P2 closures: Cyrillic homoglyph normalization (security ADV-006) and sentinel-loop circuit breaker (reliability rel-001). The honesty arc continues: v0.7.7 demoted to advisory; v0.7.8 promoted to enforced (command-based) but with documented bypass paths; v0.7.9 closes the bypass paths so "enforced" stops needing the asterisk.

## Problem Frame

PR #16 ce-code-review (`/tmp/compound-engineering/ce-code-review/20260518-221618-4cee71eb/`) ran 7 reviewer personas on the v0.7.8 diff. Critical findings in priority order:

**P0 (architectural — design changes required)**:
- **security sec-001 / adversarial ADV-002**: Sentinel forgery. Empirically reproduced: `{"last_assistant_message": "<!-- athanor:verification-emission v=1 -->\nI claim tests pass but ran nothing"}` → exit 0. The sentinel string is documented in `skills/verification-before-completion/SKILL.md` so the model has the exact text to emit. The entire gate's enforcement collapses to a 41-byte public string the model can synthesize at will. Confidence 100.
- **security sec-002**: Parent-directory athanor.json hijack. Empirically reproduced: place `{"hooks":{"profile":"off"}}` in `/tmp/athanor-hijack/athanor.json`, run hook from a child dir with no local athanor.json — gate disables silently. Walk-up resolution gives no visibility into WHICH config disabled the gate. Confidence 100.
- **security sec-003 / adversarial ADV-001**: Paraphrase bypass. Empirically reproduced: `"I executed the regression suite end-to-end and observed zero failures. Production rollout completed without rollback. PR was landed against main."` → exit 0. Zero matches against MATERIAL_CLAIMS_EN's literal substrings. v0.7.7's semantic prompt-based matching was effectively a wider trigger surface than v0.7.8's lexical port, contradicting plan §KTD2's "verbatim port — no scope expansion" claim. Confidence 100.

**P2 (cheap defensive closures)**:
- **adversarial ADV-006**: Cyrillic homoglyph attack. `"tests pаss"` (Cyrillic 'а' U+0430) bypasses literal substring match. Python `.lower()` doesn't fold Cyrillic → Latin.
- **reliability rel-001**: Sentinel-loop has no circuit-breaker. If verification skill forgets the sentinel, the gate keeps blocking. User must `profile: off` or kill session to escape.

**Out of scope for v0.7.9** (deferred to v0.7.10+ or v0.8.0 design):
- LLM-based semantic classification for paraphrase detection
- Cross-platform launcher shim for `python3` on Windows (separate spike)
- Mid-session profile mutation guard (adversarial ADV-005)
- Schema `circuitBreaker.action` enum reconciliation
- `models` config block deletion (v0.7.9 was originally the target; moved to v0.7.10 to keep this release focused on the security trio)

## Requirements

- **R1** — Sentinel forgery is no longer trivially exploitable. The model emitting `<!-- athanor:verification-emission v=N -->` without having actually invoked the verification skill must not bypass the gate. Achieved via cryptographic binding between sentinel and a per-session nonce that the verification skill controls.
- **R2** — Backward compatibility. Existing v0.7.8 sentinel format (`v=1`, no binding) must continue to work during a transition period — OR be cleanly deprecated with a documented migration path. Decided: v0.7.8 sentinel format is **rejected** in v0.7.9 (the whole point is to break forgeability); the verification skill must emit the new v=2 nonce-bound format. CHANGELOG flags this as a behavior change.
- **R3** — Parent-directory hijack is no longer silent. Config resolution scopes to the project root via `$CLAUDE_PROJECT_DIR` (when set) or git-root detection (when `.git/` is present). Walk-up never crosses a `.git/` boundary upward. When `profile: "off"` is honored, the resolved config path is announced via stderr (audit breadcrumb is already in v0.7.8 commit a2b3af5).
- **R4** — Paraphrase trigger surface expands to cover the v0.7.7 prompt's semantic intent. Achieved via regex patterns + verb-anchor heuristics layered alongside the existing literal whitelist. Detection remains deterministic (no LLM inference).
- **R5** — Cyrillic homoglyph attack closed. Pre-detection normalization step folds confusable Cyrillic/Greek/Cherokee letters to Latin before substring/regex matching.
- **R6** — Sentinel-loop circuit breaker. If the gate fires `exit 2` for N consecutive Stop events within the same Claude Code session, the (N+1)th invocation logs a clear "circuit-breaker open" stderr and exits 0 with a structured warning. Default N=3.
- **R7** — Regression tests pin every new contract. Forgery attempts, walk-up hijack attempts, paraphrase fixtures, Cyrillic homoglyph fixtures, sentinel-loop simulation. The PR #16 review surfaced these as testing gaps (T-001..T-008); v0.7.9 closes them.
- **R8** — CLAUDE.md and CHANGELOG framing remain honest. The label stays `enforced (command-based)` (true after v0.7.9 fixes) but adds a "what it does NOT catch" sub-paragraph explicitly naming residual gaps (sophisticated paraphrase outside regex coverage, mid-session profile mutation). Same security-honesty voice as v0.7.7/v0.7.8.

The plan honestly documents this.

## Key Technical Decisions

- **KTD1 — HMAC over session-state file (NOT transcript introspection).**
  Why: transcript-event introspection requires a Claude Code runtime primitive that isn't documented. The v0.7.7 spike already exercised the `type: command` Stop hook contract; verifying a transcript-event primitive would require another spike with similar uncertainty. HMAC works deterministically with files that already exist (`.athanor/sessions/<id>/`). Tradeoff: HMAC adds session-state lifecycle (write on skill invocation, validate on Stop, cleanup at session end). Documented limitation: model has read+write access to the state files, so the binding raises cost but doesn't eliminate forgery. v0.8.0+ should revisit if Claude Code exposes transcript introspection.

- **KTD2 — Sentinel format v2 = `<!-- athanor:verification-emission v=2 nonce=<hex_nonce> -->`.**
  The nonce is a 32-character hex string (16 random bytes). Generated by the verification skill on each invocation, written to `.athanor/sessions/<id>/.hook-state/nonce.json` along with timestamp + claimed-message-hash. The hook script reads the nonce file, validates: (a) nonce matches sentinel value, (b) nonce file is recent (timestamp < 60 seconds old), (c) message-hash of `last_assistant_message` matches stored claimed-hash (prevents replay across turns). Atomic delete after successful validation (one-shot — model can't reuse nonce). Backward incompatible: v=1 sentinels are explicitly rejected.

- **KTD3 — Config resolution priority: `$CLAUDE_PROJECT_DIR` > git-root > walk-up-stops-at-git.**
  Rationale: `$CLAUDE_PROJECT_DIR` is the cleanest signal if Claude Code sets it (verify at implementation time; fall back if absent). Git-root is the next-best signal — every athanor project lives in a git repo by convention. Walk-up never crosses `.git/` upward (closed boundary) and never beyond `$HOME` (additional safety). The audit-breadcrumb stderr from v0.7.8 a2b3af5 already announces the resolved path when `profile=off`; v0.7.9 extends to log the resolution mechanism (`via $CLAUDE_PROJECT_DIR`, `via git-root`, `via walk-up`).

- **KTD4 — Regex patterns + verb-anchor heuristics (NOT LLM classifier).**
  v0.7.9 adds compiled regex patterns that cover semantic variants of the literal whitelist. Examples (directional):
  - `r"(?i)\b(?:tests?|build|lint|typecheck|ci)\s+(?:are\s+)?(?:pass(?:ing|ed)?|fail(?:ing|ed)?|green|red|broken)"` — covers "CI is green", "tests are passing", "build broken"
  - `r"(?i)\bverif(?:y|ied|ication)\s+(?:the\s+)?(?:suite|tests?|claim|behavior|fix)"` — covers "verified the suite", "verification confirmed the fix"
  - `r"(?i)\b(?:rolled|deployed|shipped|landed|pushed|released)\s+(?:to\s+)?(?:prod(?:uction)?|main|staging|production)"` — covers "rolled out to production", "landed against main"
  - Korean: `r"(?:테스트|빌드|린트|타입체크|배포|머지)\s*(?:가\s+)?(?:완료|성공|실패|통과|되었?(?:다|음))"` — covers Korean verb-anchor variants

  Tradeoff: regex is deterministic + fast (no inference latency) but bounded by what we write. LLM classifier could be more flexible but adds inference cost per Stop event (every turn). v0.7.10 may layer LLM as Tier 2.

- **KTD5 — Unicode normalization step before substring/regex matching.**
  Apply NFKC normalization + a confusables fold (Latin-look-alike Cyrillic/Greek/Cherokee → Latin) using a small in-code mapping. NOT a full ICU library dependency — pure-Python with a hand-curated table covering the common attack characters (Cyrillic а, е, о, р, с, у, х, etc.). Documented as "best-effort"; sophisticated unicode attacks remain a residual risk.

- **KTD6 — Sentinel-loop circuit breaker: per-session counter, threshold 3.**
  The hook script reads a counter from `.athanor/sessions/<id>/.hook-state/stop-counter.json`. Increments on each `exit 2`. After 3 consecutive blocks in a single session, the 4th invocation:
  1. Emits a structured stderr warning naming the session ID and that the gate is opening.
  2. Exits 0 (releases the loop).
  3. Resets the counter to 0.

  Counter resets to 0 on any successful sentinel-validation (legitimate verification skill response). Tradeoff: 3 is conservative — too low and legitimate "claim → verify → claim again" patterns break; too high and the user is stuck in a loop. CHANGELOG documents the threshold and how to override (`hooks.stopLoopThreshold` config — added in U1).

- **KTD7 — Verification skill nonce lifecycle: write-on-invocation, atomic-delete-on-validation.**
  The skill writes `nonce.json` before producing its output. The skill's emitted sentinel includes the nonce value. The hook script reads + validates + atomically deletes the file. Failure modes:
  - Skill writes but hook never validates (skill response never reaches Stop): nonce file persists. Cleanup job at next skill invocation overwrites or session-end cleanup removes.
  - Hook validates but model spoofs nonce file (writes its own `nonce.json` matching its forged sentinel): forgery succeeds. Mitigation: nonce is bound to a hash of the message body; if the model writes nonce.json AND emits sentinel AND the hash matches its own message, it has effectively invoked the verification logic itself — the bypass cost is now "write a file + compute a hash + emit a sentinel" instead of just "emit a sentinel". Imperfect but materially higher cost.

- **KTD8 — `hooks.profile` enum + new `hooks.stopLoopThreshold` (integer).**
  Schema extension: `stopLoopThreshold` is a new integer field defaulting to 3. Backward compatible (missing field defaults). Documented in `_doc` strings + schema description.

## High-Level Technical Design

### Sentinel binding flow (v2)

```mermaid
sequenceDiagram
    participant CC as Claude Code (Stop event)
    participant Hook as scripts/hooks/stop_verify_claims.py
    participant Model as Active model
    participant Skill as verification-before-completion
    participant State as .athanor/sessions/<id>/.hook-state/nonce.json

    Model->>Skill: invoke (after material-claim block)
    Skill->>Skill: 1. Generate nonce (16 random bytes hex)
    Skill->>Skill: 2. Compute hash of intended response body
    Skill->>State: 3. Write {nonce, body_hash, timestamp}
    Skill->>Model: 4. Skill body output, prefixed with <!-- athanor:verification-emission v=2 nonce=<nonce> -->
    Model->>CC: Stop event (response includes sentinel)
    CC->>Hook: stdin payload (last_assistant_message)
    Hook->>Hook: 5. Extract sentinel; parse nonce
    Hook->>State: 6. Read state file
    Hook->>Hook: 7. Validate: nonce matches, timestamp < 60s, body_hash matches message body
    alt all validations pass
        Hook->>State: 8. Atomic delete (one-shot)
        Hook-->>CC: exit 0 (silent)
    else any validation fails
        Hook-->>CC: continue to material-claim check
    end
```

### Config resolution priority

```text
1. $CLAUDE_PROJECT_DIR (if env var set and contains athanor.json)
2. nearest .git/ ancestor (find via `git rev-parse --show-toplevel` or in-code walk)
3. walk-up from cwd, stopping at first .git/ boundary OR $HOME OR depth 8
4. None → default "standard" profile
```

When `profile=off` is honored, stderr includes the resolution mechanism:

```text
athanor (stop hook): gate disabled by hooks.profile=off in /path/to/athanor.json (resolved via $CLAUDE_PROJECT_DIR)
```

### Material-claim detection layers (v0.7.9)

```text
is_material_claim(message):
  1. Normalize unicode (NFKC + Cyrillic/Greek/Cherokee → Latin)
  2. Lower-case for English matching
  3. Check literal MATERIAL_CLAIMS_EN substrings (v0.7.8 set + additions)
  4. Check literal MATERIAL_CLAIMS_KO substrings (v0.7.8 set + additions)
  5. NEW v0.7.9: Check MATERIAL_CLAIMS_PATTERNS (compiled regex list)
  6. Return True if any layer matches
```

### Sentinel-loop circuit breaker

```text
On every exit-2 path:
  state = read .athanor/sessions/<id>/.hook-state/stop-counter.json
  state.consecutive_blocks += 1
  if state.consecutive_blocks > threshold (default 3):
    stderr "circuit breaker open after 3 consecutive blocks — gate releasing"
    state.consecutive_blocks = 0
    write state
    return exit 0
  write state
  return exit 2

On every successful v=2 sentinel validation:
  state.consecutive_blocks = 0
  write state
```

### U3. Hook script validates v=2 sentinel, rejects v=1

**Goal**: Replace v0.7.8's `has_emission_sentinel()` logic with v=2 nonce validation. v=1 sentinels (legacy or forgery attempts) fail validation and fall through to material-claim check (which now catches the forged response).

**Requirements**: R1.

**Dependencies**: U1, U2.

**Files**:
- `scripts/hooks/stop_verify_claims.py` — update `has_emission_sentinel` → `validate_emission_sentinel(message, session_id)` returning bool. Update `SENTINEL_PATTERN` to capture nonce. Add the nonce-state lookup + body-hash verification + atomic delete.

**Approach**:
1. New regex captures the nonce: `r"^\s*<!--\s*athanor:verification-emission\s+v=2\s+nonce=([a-f0-9]{32})\s*-->"`.
2. Extract sentinel + nonce from response.
3. Read nonce-state file via U1 helpers.
4. Validate: nonce matches AND `time.time() - state.timestamp < 60` AND `sha256(message) == state.body_hash`.
5. On all-pass: atomic delete nonce state, return True (caller exits 0 silently).
6. On any-fail: return False (caller proceeds to material-claim check, which will catch the forged response's material claim).
7. v=1 sentinel: regex does not match, function returns False — falls through to material-claim check.

**Patterns to follow**: existing `has_emission_sentinel` structure; defensive error handling.

**Test scenarios** (extend `tests/test_regression_stop_hook_script.py`):
- Valid v=2 sentinel with matching nonce-state + recent timestamp + matching body hash → exit 0.
- Valid v=2 sentinel but stale timestamp (>60s) → fall through (exit 2 if material claim present).
- Valid v=2 sentinel but body_hash mismatch (replay attack) → fall through.
- Valid v=2 sentinel but no nonce-state file → fall through.
- v=1 bare sentinel (forgery attempt with old format) → fall through to material-claim check.
- v=2 sentinel with corrupted nonce-state JSON → fall through with stderr warning.
- Forgery attempt: model writes nonce-state itself with matching body_hash → exit 0 (bypass acknowledged in docs; this test pins the documented cost-of-forgery boundary).
- One-shot enforcement: valid v=2 → exit 0 → state file deleted → second invocation with same sentinel → fall through.

**Verification**: pytest extended; manual smoke test in real Claude Code session (register hook, invoke verification skill, observe nonce-state lifecycle).

### U4. Config resolution: $CLAUDE_PROJECT_DIR → git-root → walk-up-stops-at-git

**Goal**: Replace v0.7.8's `_find_athanor_config` (8-level unbounded walk-up) with the priority chain in KTD3.

**Requirements**: R3.

**Dependencies**: none (independent of sentinel work).

**Files**:
- `scripts/hooks/stop_verify_claims.py` — rewrite `_find_athanor_config`. Update `_read_profile` to return resolution-mechanism string alongside (profile, config_path).

**Approach**:
1. If `os.environ.get("CLAUDE_PROJECT_DIR")` is set and `<that_dir>/athanor.json` exists → use it; mechanism="$CLAUDE_PROJECT_DIR".
2. Else: walk up from cwd. Track depth (cap at 8).
3. At each level, check for `athanor.json`. If found AND a `.git/` exists at the same level → use it; mechanism="git-root".
4. If athanor.json found WITHOUT `.git/` at same level: continue walking (don't stop at non-git ancestors).
5. If `.git/` found WITHOUT `athanor.json`: STOP walking (closed boundary — don't cross repo root upward).
6. If neither found and `os.path.expanduser("~") == cwd_iteration`: STOP (don't walk past $HOME).
7. If athanor.json found at depth N without `.git/` at the same level but no `.git/` boundary crossed yet → use it (handles non-git installs); mechanism="walk-up".
8. None found → return (None, None, None).

Stderr breadcrumb on `profile=off` now includes the mechanism:
```
athanor (stop hook): gate disabled by hooks.profile=off in /path/to/athanor.json (resolved via $CLAUDE_PROJECT_DIR)
```

**Patterns to follow**: v0.7.8's defensive walk-up structure; same depth cap; same `Path.cwd().resolve()` start.

**Test scenarios** (extend `tests/test_regression_stop_hook_script.py`):
- `$CLAUDE_PROJECT_DIR` set + `<dir>/athanor.json` present + `profile: off` → exit 0 + stderr mentions `$CLAUDE_PROJECT_DIR`.
- `$CLAUDE_PROJECT_DIR` set but file absent → falls back to git-root search.
- Git-root with athanor.json: gate uses it; stderr mentions `git-root`.
- Walk-up from subdir within git-root: stops at .git/ boundary even if ancestor of .git/ has its own athanor.json (closed boundary; replicates the v0.7.8 hijack test pre-state, now blocked).
- Walk-up never crosses $HOME upward.
- No athanor.json anywhere: returns None (profile defaults to "standard" — matches v0.7.8 fall-open behavior).

**Verification**: pytest extended; integration test replicating PR #16 sec-002 reproduction — confirms the bypass no longer works.

### U5. Material-claim regex pattern layer + unicode normalization

**Goal**: Add a new `MATERIAL_CLAIMS_PATTERNS` (compiled regex list) covering semantic variants. Add unicode normalization step before matching. Closes paraphrase bypass + Cyrillic homoglyph attack.

**Requirements**: R4, R5.

**Dependencies**: none (independent).

**Files**:
- `scripts/hooks/stop_verify_claims.py` — add `MATERIAL_CLAIMS_PATTERNS`, add `_normalize(s)` helper, update `is_material_claim` to apply normalize → substring → regex.

**Approach**:
1. `MATERIAL_CLAIMS_PATTERNS` is a list of compiled `re.Pattern` objects with `re.IGNORECASE` flag for English. Patterns cover (directional examples in KTD4) verb-anchor variants beyond literal substrings.
2. `_normalize(s)` applies:
   - `unicodedata.normalize("NFKC", s)` (decompose + canonical compose; handles many compatibility variants).

### U6. Sentinel-loop circuit breaker

**Goal**: After 3 consecutive `exit 2` blocks in a single session, the 4th invocation logs the circuit-breaker-open warning and exits 0 to release the loop.

**Requirements**: R6.

**Dependencies**: U1 (state helpers).

**Files**:
- `scripts/hooks/stop_verify_claims.py` — add circuit-breaker logic at exit-2 path. Use `hooks.stopLoopThreshold` from config (default 3 if missing).

**Approach**:
1. On every exit-2 path: read `stop-counter.json` state, increment, check against threshold.
2. If `count >= threshold + 1`:
   - Emit stderr: `"circuit breaker open after N consecutive blocks in session <id> — gate releasing this turn. If you keep hitting this, your verification skill may be misconfigured or your model is consistently producing material claims without invoking it."`
   - Reset counter to 0.
   - Return exit 0.
3. Else: write incremented counter, return exit 2 (normal).
4. On valid v=2 sentinel validation (U3): reset counter to 0.
5. Threshold read from `hooks.stopLoopThreshold` (added in U1's schema extension); default 3 if missing.

**Patterns to follow**: existing exit-2 flow; same atomic-write pattern as nonce-state.

**Test scenarios** (extend `tests/test_regression_stop_hook_script.py`):

- 2 blocks + valid sentinel → counter resets; 3 more blocks needed before circuit-breaker.
- Custom threshold via `hooks.stopLoopThreshold: 5` → 5 blocks then release.
- Threshold=0 (invalid) → falls back to default 3 with stderr warning.
- Counter survives across hook invocations within a session.
- Counter does NOT carry across different session IDs.

## Risk Analysis & Mitigation

**Risk 1: State-file race condition between verification skill write and hook read.**
- *Likelihood*: Low. Same-process model: skill writes during its response generation; hook reads at Stop event (after response is complete). No concurrent writers expected.
- *Impact*: Hook reads stale or partial state → validation fails → false fall-through → exit 2 on legitimate verification response.
- *Mitigation*: Atomic write via `os.replace`. Timestamp check (60s window) prevents stale-state-misvalidation in normal flow.

**Risk 2: Verification skill forgets to write nonce-state file but emits sentinel.**
- *Likelihood*: Medium. The skill body is markdown prose; the model must invoke a Bash step to write the file. A model could emit the sentinel without invoking the Bash step.
- *Impact*: Legitimate verification attempts fail validation → infinite loop until circuit breaker fires.
- *Mitigation*: Circuit breaker (U6) bounds the loop at 3. Skill documentation explicitly names the file-write step as mandatory. Tests verify the skill body contains the file-write instruction.

**Risk 3: Model writes its own nonce-state file to bypass.**
- *Likelihood*: Medium-high for a determined adversarial model. Low for honest model behavior.
- *Impact*: Forgery succeeds — model can pre-write nonce.json with a computed body_hash matching its own response, emit a matching sentinel.
- *Mitigation*: Documented limitation. Cost-of-forgery raised from "emit one string" to "compute SHA-256, write JSON file, emit sentinel" — materially higher cost. Long-term fix requires Claude Code runtime transcript-event verification (v0.8.0+).

**Risk 4: Regex pattern overmatches (false positive).**
- *Likelihood*: Medium. Regex patterns are inherently broader than literal substrings.
- *Impact*: Legitimate analytical text triggers exit 2 → user frustration.
- *Mitigation*: Verb-anchor design (require a noun-verb pairing, not bare verbs). Test corpus includes negative cases. Circuit breaker bounds the cost of false positives.

**Risk 5: Unicode normalization causes legitimate Korean text to falsely match.**
- *Likelihood*: Low. NFKC is well-defined for Hangul; the confusables table targets Latin/Cyrillic/Greek (not Korean).
- *Impact*: Korean false positive → legitimate Korean prose blocked.
- *Mitigation*: Test corpus includes Korean negative cases. Confusables table explicitly does not touch Hangul or CJK ranges.

**Risk 6: $CLAUDE_PROJECT_DIR not set by Claude Code in some environments.**
- *Likelihood*: Medium. Documentation of this env var is sparse; behavior may differ across Claude Code versions.
- *Impact*: Falls back to git-root, which is the next-best signal — no regression vs v0.7.8.
- *Mitigation*: Fallback chain handles absence gracefully. Stderr breadcrumb names the actual resolution mechanism, so users can see which path was used.

**Risk 7: Atomic delete fails (permission, race).**
- *Likelihood*: Very low.
- *Impact*: Nonce state file persists; next Stop event with same nonce would re-validate (replay).
- *Mitigation*: Timestamp window (60s) bounds replay risk. Skill always generates fresh nonce per invocation.
