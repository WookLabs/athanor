# feat: v0.11.1 — using-superpowers boundary clarification

## Summary

v0.10.0에서 흡수된 `superpowers:using-superpowers` skill은 SessionStart에
자동 로드되어 "ABSOLUTELY MUST invoke" 톤을 강제한다. 이 톤은
athanor-native 11 skill의 Thin Leader + planner-classified discipline과
voice 차원에서 어긋난다. v0.11.1은 그 boundary를 advisory 라벨로
문서화한다 — runtime gate 추가 없음, upstream 편집 없음, sp-* 거취 결정
없음. 산문 + lock-in tests 중심의 작은 release.

---

## Problem Frame

(요약. 자세한 내용은 origin §Problem Frame.) v0.11.0 후 athanor-native
skill 호출 시 using-superpowers "MUST" rule이 Thin Leader dispatch보다
우선하는지 ambiguous. 사용자의 "athanor만 쓸거야" trajectory와 결합하면
ergonomic 마찰로 표면화 예정. documentation + preamble level에서 닫는다.

## Decisions (resolves origin OQ1-OQ3)

- **D1 (OQ1 — preamble wording).** 모든 9 native Thin Leader SKILL.md에 동일한
  canonical paragraph 1개. 영문 + 코드인용 mix (기존 SKILL.md 보이스
  유지). 정확히:

  ```
  ### v0.11.1 using-superpowers boundary

  Athanor's Thin Leader + planner-classified discipline applies in this
  skill context. `superpowers:using-superpowers` is loaded at SessionStart
  and its "MUST invoke before response" pressure is **advisory here** —
  discovery in athanor-native skills resolves through leader dispatch,
  not pre-response invocation check. See CLAUDE.md §Defense Mechanisms.
  ```

- **D2 (OQ2 — CLAUDE.md placement).** §Defense Mechanisms 표에 새 row
  추가 + 표 직후 상세 단락 (기존 Spec-then-TDD Discipline 패턴 답습).
  row label: `using-superpowers boundary`; status: `advisory
  (preamble-declared)`.

- **D3 (OQ3 — test 파일 분리).** 신규
  `tests/test_regression_v011_1_using_superpowers_boundary.py` 로 분리.
  근거: v010_honesty_arc.py는 release-prose voice 검사 단일 책임;
  preamble presence + signal phrase는 별도 응집성.

- **D4 — signal phrase 정의.** CLAUDE.md boundary 단락이 포함해야 할
  4 signal phrase (R1):
  1. `using-superpowers`
  2. `SessionStart`
  3. `advisory`

  Preamble canonical (R2)이 포함해야 할 signal phrase (1회):
  - `using-superpowers boundary` (heading) 또는 본문의 `advisory here`.
