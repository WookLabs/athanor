# feat: v0.10.0 — Absorb compound-engineering + superpowers into athanor (full merge, identity-preserving)

## Summary

athanor v0.10.0 absorbs **compound-engineering v3.8.3** (~36 skills + ~40 sub-agents) and **superpowers v5.1.0** (14 skills) into the athanor plugin as a vendored superset. The user explicitly confirmed **full merge** semantics — every CE skill and every superpowers skill must be reachable from athanor without depending on those external plugins being installed. At the same time the user named four athanor-specific identity commitments that must survive the absorption intact:

1. **Thin Leader architecture commitment** (leader dispatches; workers execute in clean contexts).
2. **Cross-model adversarial planning** (Planner A Claude + Planner B Codex in parallel + cross-review + Critic synthesis — currently `/athanor:deep-plan`).
3. **Spec-then-TDD discipline + honesty arc** (Splitter `execution_note` classification, conjunction-of-three Phase 3 gate, advisory/enforced label honesty arc with negative-assertion regression tests).
4. **Stop hook runtime gate** (`scripts/hooks/stop_verify_claims.py` + v=2 nonce-bound sentinel + circuit breaker — the only "enforced" defense mechanism in the project).

The plan structures the absorption so all four survive on top of, not underneath, the vendored material. This is not a rebrand — vendored skills keep MIT provenance + upstream attribution; athanor remains a distinct identity that happens to ship a superset of CE+superpowers skill surface.

---

## Problem Frame

Today the user runs athanor and CE side-by-side: athanor for plan/work/discuss/review with its identity commitments; CE for the 20+ skills athanor doesn't have (autofix code review, 18 reviewer personas, LFG end-to-end pipeline, ce-test-browser, ce-proof HITL, ce-strategy, ce-ideate, ce-doc-review, frontend-design / figma-sync / demo-reel, sessions, pulse, etc.). The split has friction:

- **Discoverability split** — users have to know which plugin owns which capability; commands like `/athanor:plan` vs `/ce-plan` mean choosing twice.
- **Identity erosion risk** — if CE keeps evolving and athanor doesn't absorb, CE skills start to win adoption purely by breadth even when athanor's architecture (Thin Leader, cross-model, runtime defense) would have been the better fit for a given task.
- **Honesty arc fragility** — athanor's v0.7.7~v0.9.0 honesty-arc commitment (advisory vs enforced labels with negative-assertion regression locks) lives in athanor's prose; vendored CE prose has its own voice and could silently overclaim through label drift if not audited at vendor-time.
- **Maintenance asymmetry** — athanor's existing T2 vendoring pattern (provenance block + source-commit + license + modifications) is already proven for one skill (`verification-before-completion`) and two reference files (`clarify-gap-probes.md`, `requirements-capture.md`). Scaling that to ~50 vendored files requires explicit batching, not ad hoc absorption.

This work is **cross-cutting** (touches every skill directory, manifests, hook layer, CLAUDE.md, STATE.md, CHANGELOG.md), **identity-risk-high** (athanor could become "CE in a wig" if guardrails aren't enforced), and **license-sensitive** (every vendored file must carry honest provenance under MIT). Depth: **Deep**.

## Key Decisions

- **D1 — Vendoring directory layout.** All vendored files land under `skills/vendored/<source>/<skill>/` and `agents/vendored/<source>/<agent-file>`. Rationale: keeps native athanor skills (`skills/discuss/`, `skills/plan/`, etc.) cleanly separated from vendored material so an audit can grep `skills/vendored/` and see the full absorption surface without false positives. Existing already-vendored content (`skills/verification-before-completion/`, `skills/discuss/references/clarify-gap-probes.md`, `skills/discuss/references/requirements-capture.md`) stays where it is — moving it would dirty the v0.7.8/v0.9.0 git history for no functional gain; only new v0.10.0 vendoring uses the new layout. Document the discrepancy in CLAUDE.md.
- **D2 — Naming/namespace policy for command collisions.** Where athanor and CE both ship the same capability (`/athanor:plan` vs CE `/ce-plan`, `/athanor:work` vs `/ce-work`, etc.), the **athanor-native skill keeps the unprefixed slot** (`/athanor:plan` remains the cross-model adversarial dual-planner), and the vendored CE variant exposes as `/athanor:ce-plan`. Users who explicitly want the CE single-planner flow can still reach it without losing athanor's default identity. For skills with no native athanor equivalent (ce-test-browser, ce-strategy, ce-ideate, etc.), the namespace is `/athanor:ce-<name>` straight (no native collision). Superpowers skills similarly land as `/athanor:sp-<name>`. The "sp-" prefix is shorter than "superpowers-" and distinctively non-CE.
- **D3 — Identity preservation as a guard layer, not as edits to vendored content.** Vendored CE/superpowers files are NOT modified to "fit" athanor's identity (modifying them would invalidate the T2 provenance — they wouldn't be vendored, they'd be forked). Instead, athanor-native wrapper skills enforce identity: e.g., `/athanor:ce-plan` is a thin athanor wrapper that delegates to vendored CE `ce-plan` SKILL.md content but injects Thin Leader pre-checks at the wrapper level. This is identical to how Python packaging vendors a library: the library stays verbatim; the wrapper handles host integration.
- **D4 — Cross-model adversarial planning stays the athanor default.** Even after vendoring CE's `ce-plan` (single-agent flow) as `/athanor:ce-plan`, the user-facing `/athanor:plan` continues to dispatch Planner A (Claude) + Planner B (Codex) + Critic per athanor v0.7.x~v0.9.0. Users who explicitly want the CE single-agent flow type `/athanor:ce-plan`. No silent downgrade.
- **D5 — Spec-then-TDD discipline stays athanor-native.** Vendored CE `ce-work` becomes `/athanor:ce-work` (CE-style execution); athanor-native `/athanor:work` remains the Splitter+execution_note+conjunction-of-three-gate flow. CE's execution posture signals (per their AGENTS.md / SKILL.md prose) are NOT auto-applied to athanor-native work — they only apply when the user explicitly invokes `/athanor:ce-work`.
- **D6 — Stop hook stays enforced and stays athanor-property.** Vendoring superpowers' `verification-before-completion` skill (which already exists under `skills/verification-before-completion/` from v0.7.8) does NOT extend the Stop hook to fire on superpowers skills' material claims — the hook still triggers on athanor-native skill output. Superpowers prose-style verification is vendored but disconnected from the runtime gate. Honesty: this means CE-vendored / superpowers-vendored skills run without the Stop hook protection that athanor-native skills enjoy. Document this trade-off explicitly in CLAUDE.md §Defense Mechanisms.
- **D7 — Provenance / license / honesty arc enforcement at vendor time.** Every new vendored file gets the athanor T2 provenance block (per `skills/verification-before-completion/SKILL.md` and `skills/discuss/references/clarify-gap-probes.md` precedents): `<!-- Provenance: upstream / source-commit / license / modifications / t0-t1-disproof -->`. Source-commit recorded as the upstream plugin's version tag (CE 3.8.3, superpowers 5.1.0) plus the file's last-modified upstream commit when reachable from upstream GitHub. Regression test asserts every file under `skills/vendored/**` has a provenance block.
- **D8 — Honesty arc extends to v0.10.0.** Negative-assertion regression tests added: "v0.10.0 does NOT claim CE/superpowers absorption converted advisory mechanisms to enforced." The CHANGELOG v0.10.0 entry uses precise language: "vendored ~50 skills from CE 3.8.3 and superpowers 5.1.0; vendored content runs without athanor's Stop hook gate; honesty arc preserved." NOT "athanor now supports all CE features" — too broad, false sense of integration.
- **D9 — Marketplace impact: single plugin entry, expanded skill surface.** athanor stays a single plugin in the marketplace. `marketplace.json` skill inventory grows from ~11 entries to ~50+. Plugin description updated: "Self-sustaining agentic workflow orchestrator with absorbed CE + superpowers skill surface (vendored under athanor namespace; cross-model adversarial planning core; Stop hook runtime defense)."
- **D10 — Phased delivery via Implementation Unit boundaries.** Because of the size (~50 vendored files, ~40 agents, multiple manifests, 8+ doc files, 30+ new regression assertions), execute in 6 phases (M1–M6) with explicit checkpoint commits. Each phase ends with full regression suite green. Phases M1–M2 are foundation and identity protection — these CANNOT be skipped or reordered. M3–M5 are bulk vendor work that can parallelize internally. M6 is regression + release.

## Risk Analysis & Mitigation

| Risk | Severity | Mitigation |
|---|---|---|
| Identity erosion: athanor-native `/athanor:plan`/`/athanor:work`/`/athanor:discuss` silently inherit CE behavior | **High** | U5–U8 guard prose + T1–T4 regression tests. Tests fail the build if athanor-native skill bodies were modified to dispatch to CE flows. |
| Provenance drift: future contributor copies new CE upstream content without provenance block | High | `tests/test_regression_vendor_provenance.py` (U23) — every `skills/vendored/**/SKILL.md` must start with a valid provenance block. Build fails otherwise. |
| Stop hook false negatives on vendored skill output | Medium | Honesty disclosure in CLAUDE.md per D6 + U8. Deferred to v0.10.1+ (vendor-aware whitelist). |
| Plugin load time growth (~50 skills) | Medium | `/athanor:setup` health check measures load time; warn at >2s. |
| License-attribution gap (upstream releases new files, athanor's NOTICE drifts) | Medium | NOTICE.md (U4) lists upstreams + versions; drift-check process documented in STATE.md (U19). |
