# P13 Live Command Trace Emitters Design

Date: 2026-06-17
Branch: `feat/p13-live-command-trace-emitters`
Status: design for implementation

## Goal

Move Athanor's workflow trace layer from fixture-only toward live command
instrumentation by adding a local, read/write trace emitter CLI and by wiring
the core command skills to call it at stable lifecycle points.

P13 is still local-first. It does not add external telemetry, new default hooks,
OpenTelemetry export, model-judge evals, or live SDK session orchestration.

## Why This Is Next

P6 created the trace schema and deterministic scenario runner. P10 added trend
snapshots and trace-to-scenario promotion. P12 added a runtime execution
adapter. The remaining observability gap is that live `/athanor:*` command
flows still do not have a concrete way to emit trace records as they execute.

Claude Code skills/custom commands are prompt-based procedures. They can run
tools and shell commands, but they are not Python functions that Athanor can
wrap directly. Claude Agent SDK hooks can log lifecycle events, but broadening
default hooks would increase runtime cost and policy risk. The safest P13 layer
is therefore a small local CLI that command leaders invoke explicitly.

## External Baseline

Recent official and high-signal references reinforce the same design:

- Claude Code skills are the current custom command surface. A `SKILL.md`
  procedure creates a slash-command style workflow and can use allowed tools.
- Claude Agent SDK hooks are the lifecycle surface for automatic logging and
  control, but hooks should stay scoped because they run around every matched
  event.
- OpenAI Agents SDK tracing records end-to-end workflow traces, agent spans,
  tool calls, handoffs, guardrails, and custom events.
- OpenTelemetry GenAI conventions emphasize workflow, conversation, model,
  token, and event attributes, but the conventions are still a moving target
  and content fields are sensitive.

Implication: Athanor should emit local structured command events first, then
map/export them later in P14.

## Design Choices

### Approach A: Add More Default Hooks

Rejected for P13. Hooks can observe tool calls and session lifecycle, but a
default hook expansion would affect every user session. Athanor's strongest
property is conservative default cost. Keep hooks narrow until live traces show
which event surfaces earn promotion.

### Approach B: Replace Command Skills With A Python Runtime

Rejected. Athanor is packaged as Claude Code skills and plugin files. Rewriting
the commands as an external orchestrator would create a second product surface
and bypass the existing thin-leader workflow.

### Approach C: Local Trace Emitter CLI Plus Skill Anchors

Selected. Add a stdlib-only `scripts/evals/emit_workflow_trace.py` CLI. Core
command skills call it at command start, dispatch, verification/escalation, and
finish points. The CLI uses the existing `TraceWriter`, preserves the P6 schema,
adds optional command/session metadata, and writes JSONL under `.athanor/traces`
by default.

## Trace Record Contract

Keep `schema_version: 1`. P13 adds optional fields, not a schema break:

- `timestamp`: ISO-8601 UTC timestamp generated by the emitter.
- `command`: command identity, such as `plan`, `work`, `review`, `lfg`, or
  `lfg-goal`.
- `session_id`: Athanor session or goal id.
- `worker_id`: optional worker/session id for dispatched workers.
- `parent_seq`: optional positive integer for a child event's parent record.
- `duration_ms`: optional non-negative integer when the command can measure it.

The existing required fields remain unchanged:

- `schema_version`, `trace_id`, `seq`, `phase`, `event_type`, `actor`,
  `status`, and `message`.

## Emitter CLI

Example:

```bash
python scripts/evals/emit_workflow_trace.py \
  --session-id 2026-06-17-001 \
  --command work \
  --phase work \
  --event-type workflow.started \
  --actor leader \
  --status started \
  --message "work execution started" \
  --json
```

Default path:

```text
.athanor/traces/<session-id>.jsonl
```

If `--trace-path` is provided, the emitter writes exactly there. If
`--trace-id` is omitted, it derives `athanor-<session-id>` or
`athanor-live`.

Exit codes:

- `0`: event emitted.
- `2`: invalid arguments, invalid evidence JSON, or invalid trace record.

## Command Skill Anchors

Each command should emit at least:

- `workflow.started` when the command resolves its session/id.
- `agent.dispatched` or `worker.started` when it dispatches workers.
- `verifier.result`, `gate.evaluated`, `review.result`, or `loop.decision`
  when the command reaches its main evidence point.
- `escalation.required` when the command cannot honestly continue.
- `workflow.finished` before final summary.

The command skills should not claim tracing is exhaustive. P13 gives them a
shared local event writer and required lifecycle anchors.

## Non-Goals

- No OpenTelemetry export. P14 owns vocabulary/export.
- No new default hooks.
- No SDK-based command launcher.
- No model-judge eval gate.
- No external telemetry dependency.
- No mandatory trace emission for non-Athanor commands.

## Architecture Review

This design closes the live trace gap in the smallest durable step. It keeps
Athanor's local deterministic gates, uses the existing P6 trace writer, and
avoids increasing hook cost. The main risk is that skill-based leaders may
forget to run the emitter. P13 mitigates that with command skill anchors and
tests that assert the anchors stay present. Later P14/P15 work can then export
or package the traces without changing the command contract again.
