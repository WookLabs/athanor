# Athanor v0.18.0 Migration Guide

v0.18.0 ships the **Freeze infrastructure** stage — a per-session,
plan-scoped editing envelope for Claude file tools (`Edit` / `Write`
/ `MultiEdit` + conservative `Bash` write patterns). The feature is
**opt-in**: existing users see no behavior change until they flip a
single config key.

## TL;DR

| You used to do | Now you can do | Notes |
|---|---|---|
| Rely on advisory scope-drift skill only | Set `hooks.freeze.mode = "session"` to **enforce** per-session scope | Opt-in; default stays `"off"`. |
| Manually audit worker file writes after the fact | Reject out-of-scope Claude tool writes **at PreToolUse** | Exit 2 from `pretool_dispatcher.py` -> `freeze_guard.py`. |
| Use single PreToolUse hook (v0.16.0 Kernel Guard) | Same Kernel Guard runs FIRST inside the new dispatcher | No behavior change for v0.16.0 catastrophic class. |

## Enabling Freeze

1. Set the mode in `athanor.json`:

   ```json
   {
     "hooks": {
       "freeze": {
         "mode": "session",
         "extraAllowedPaths": []
       }
     }
   }
   ```

   Default remains `"off"`. The freeze evaluator is silent and the
   allowlist is built but not enforced when `mode == "off"`. Flipping
   to `"session"` later (mid-session) immediately starts enforcing the
   allowlist that's already on disk.

2. Run `/athanor:work` as normal. The Step 0.6 builder writes
   `.athanor/sessions/<id>/freeze-allowlist.json`.

3. When the worker dispatches an `Edit` / `Write` / `MultiEdit` /
   gated `Bash` write whose destination path falls outside the
   allowlist, the dispatcher rejects with exit 2 + stderr fed back
   to the worker as continuation context.

## Allowlist Format

The builder writes a JSON object at
`.athanor/sessions/<id>/freeze-allowlist.json`:

```json
{
  "session_id": "2026-05-29-001",
  "allowed_paths": [
    "skills/work/SKILL.md",
    "tests/test_regression_v018_freeze_step_06.py",
    ".athanor/sessions/2026-05-29-001/**"
  ],
  "built_at": "2026-05-29T12:00:00Z",
  "subtask_count": 8
}
```

Composition (union, deduped, normalized to project-relative POSIX):

1. All subtask `files:` entries from the `## Subtasks` block of
   `plan.md`.
2. Session-local defaults (the session directory itself plus its
   subdirectories — work-log, discoveries, etc).
3. User extras from `athanor.json` `hooks.freeze.extraAllowedPaths`.

Missing `files:` for a subtask is **not an error** — it becomes an
empty list and the allowlist falls back to defaults + extras only.

## D2 Honesty Residual

Freeze is documented as **"Claude file-tool allowlist"**, not "editing
envelope". Two classes of writes are NOT gated and users should know:

### Codex stage uneven enforcement (D2)

`/athanor:lfg` Step 1 invokes `/athanor:plan` which dispatches Codex
subprocess workers. Codex writes its plan-b.md / review files via its
own subprocess — those writes are **not visible to Freeze**. The
Freeze guard only intercepts Claude `Edit` / `Write` / `MultiEdit`
calls. This is the documented D2 residual.

### Bash subprocess writes

The Bash guard gates **conservative, visible-destination** patterns
only: `>`, `>>`, `tee FILE`, `cp SRC DST`, `mv SRC DST`, `mkdir DIR`,
`touch FILE`. The following bypass the guard because the destination
path is not syntactically visible in the Bash command string:

- `python -c "open('out.txt', 'w').write('x')"`
- `make build` (Makefile-driven writes to `build/`, `dist/`, etc)
- `codex exec ...` (Codex CLI dispatches)
- `git apply patch`
- `npm run ...`, `cargo build`, etc.

This is an **explicit honesty residual**, not a bug. The v0.19.0
PostToolUse sniffer records test-execution evidence after Bash returns and
records file-change observations when the PostToolUse payload exposes
structured file-change fields. Missing file-change evidence remains normal,
and observed out-of-allowlist paths are reported as concerns rather than
new blocking behavior.

## Deferred (v0.18.1 and v0.18.2)

Per Critic synthesis on the v0.18.0 deep-tier plan, both reviewers
converged on shipping the Freeze stage now and deferring the next two
stages behind admission criteria. See `docs/ROADMAP.md` for full
admission criteria text. Summary:

- **v0.18.1 — git-worktree isolation per subtask.** Admission triggers:
  freeze-violations.jsonl >= 10 across >= 5 sessions, OR 1
  user-reported issue with reproduction, OR `/athanor:work --team`
  same-file collision documented.
- **v0.18.2 — UserPromptSubmit injection.** Design precondition: live
  spike capturing real UPS payload shape. The v0.17.0
  `capability_probe.py` shows UPS `supported=false` passively, so a
  live invocation spike is required before design work begins.

## Capability Probe Re-run

The passive capability probe shipped in v0.17.0 records what athanor
knows about Claude Code hook event classes. Re-run it after v0.18.0
install to refresh `.athanor/hook-capability.json` with the new
PreToolUse dispatcher entries:

```bash
# Inside the project where athanor is installed
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/hooks/capability_probe.py"

# Or as part of the standard health check
/athanor:setup
```

The probe is passive — it inspects existing artifacts (`hooks/hooks.json`,
`CLAUDE.md`, `docs/STATE.md`, etc.) rather than triggering Claude Code
hook events itself. Empirical validation of each event class is
deferred to per-event spikes following the 2026-05-18 Stop hook spike
methodology.

When `PostToolUse` is registered, the report marks it as `evidence-only`
support and includes `evidence_streams` summaries for the redacted JSONL
streams already on disk. The expected payload key list is labeled with
`payload_keys_source: "expected"`, while `tool_response_available` remains
`null` until live Claude Code payload evidence proves the response shape.

## What got added

- `scripts/work/build_freeze_allowlist.py` — per-session allowlist
  builder, stdlib-only.
- `scripts/hooks/pretool_dispatcher.py` — single outer entry for
  PreToolUse events. Kernel-FIRST dispatch order.
- `scripts/hooks/freeze_guard.py` — Claude file-tool + conservative
  Bash write gate.
- `hooks.freeze` config block (athanor.json + templates/athanor.json
  + schema).
- `skills/work/references/freeze.md` — load-bearing prose contract.
- 11 new regression test files (see `CHANGELOG.md` v0.18.0 entry).

## What stayed the same

- **v0.16.0 Kernel Guard catastrophic class.** Destructive shell,
  force-push, credentials — gated by Kernel Guard which runs FIRST in
  the dispatcher. Behavior unchanged; default fail-CLOSED on missing
  config unchanged.
- **Stop hook runtime gate (v0.7.7 + v0.11.3 + v0.11.4 companion-fix
  arc).** Stop event handling untouched.
- **Spec-then-TDD discipline.** Splitter classification + Phase 3
  conjunction gate unchanged. Freeze is **orthogonal** — it gates
  *where* writes can go, not *whether* tests run.
- **Thin Leader contract.** Leader does NOT do implementation work
  directly. Freeze enforces this contractually for Claude tool writes.
